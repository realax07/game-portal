# Манчкин — Подземная таверна

Локальная браузерная фанатская игра на русском языке. Без установки зависимостей и без сборки.

План развития и точка продолжения: [BACKLOG.md](BACKLOG.md). Дополнения проходим по одному: сначала полный состав и механики, затем иллюстрации.

## Запуск

Нужен Node.js 20 или новее:

```sh
npm run dev
```

Открыть http://localhost:4387. Для другого порта: `PORT=4390 npm run dev`.

- 1–5 игроков: одиночная тренировка, человек против ботов или игра за одним экраном.
- 62 выбираемых набора классического фэнтезийного Манчкина. По умолчанию включены только базовый, Munchkin 2: Unnatural Axe и Munchkin 3: Clerical Errors. Каталог сворачивается; есть поиск по набору или карте, выбор всех и возврат к исходным трём.
- 288 названий карт, оригинальные карикатуры для ключевых карт и 280 SVG-иллюстраций Game-icons для остальных, анимации, звуки по кнопке, шуточный журнал.
- Снаряжение, классы и расы, бой, зелья, помощь за сокровище, смывка, проклятия, продажа и милостыня.
- Победа на 10-м уровне за победу над монстром.
- Автосохранение партии в localStorage браузера; продолжение через лобби.
- Адаптивная вёрстка и поддержка prefers-reduced-motion.

## Объём адаптации

Это играбельная упрощённая фанатская версия, а не полная цифровая реализация настольной игры. Используется подборка реальных названий, а не полные оригинальные колоды. Русские названия — описательные переводы. Тексты, часть числовых параметров, баланс и эффекты адаптированы. Оригинальные сканы и иллюстрации не используются.

Видимые пустые и занятые слоты: головняк, броня, обувка, две руки, скакун и наёмник. Двуручное оружие занимает обе руки, бонус считается один раз. При заполненных руках можно выбрать оружие для замены. Классы и расы показаны отдельно, вместе с картой расширения. Суперманчкин / Полукровка дают два места, Ультраманчкин / Третьекровка — три, Супер-пуперманчкин / Химера снимают лимит. Для расширения нужна хотя бы одна соответствующая идентичность. Дубликаты одинакового класса или расы запрещены. Снятие расширения оставляет первую идентичность, возвращая остальные в руку; это намеренное упрощение настольного сброса. Усиления Master / Dark требуют соответствующей идентичности. Все снятые вещи возвращаются в руку, снаряжение меняется вне боя. У всех 15 классов и рас есть работающие эффекты. Активные действия, стоимость и условия показаны под рукой; мультиклассы и мультирасы объединяют эффекты. Полный список и ограничения описаны в [reference/rules/implemented.md](reference/rules/implemented.md). Новые подборки используют адаптированные значения и эффекты. Подземелья вводятся через колоду дверей и меняют силу следующих монстров. Усилители меняют текущего монстра, положительные дают дополнительное сокровище. Побочные задания дают дополнительное сокровище за перевес в пять единиц или полную экипировку. Это не реализация оригинальных подсистем подземелий, заклинаний, боссов и заданий. Нет торговли и полного набора индивидуальных способностей каждой печатной карты; подрезки и воровство реализованы. Реализованы подкидывание монстров и усилители в чужом бою. Проверенные шмотки имеют печатную цену, для остальных пока используется 500 золотых; 1000 золотых дают уровень до девятого. Неудачная смывка стоит уровня; дракон забирает вещи; классы и расы сохраняются, новая рука 4+4 выдаётся в свой следующий ход. Боты выбирают экипировку с учётом ограничений и условных бонусов, используют способности, продают лишнее, выбирают выгодных монстров, просят помощь и мешают соперникам.

Число карт в колодах включает несколько экземпляров каждого названия. На старте каждый получает 4 двери и 4 сокровища. Двери и сокровища имеют отдельные сбросы. При опустошении перемешивается только сброс соответствующей колоды, без создания новых экземпляров. Пустая колода с пустым сбросом ничего не выдаёт.

Данные партии остаются в браузере. Сервер слушает только 127.0.0.1. Шрифты загружаются с Google Fonts; при отсутствии сети используются системные.

## Каталог и совместимость сохранений

`public/data/publisher-catalog.json` хранит открытые списки **названий** с официальных страниц и ссылки на источники. `public/catalog.js` содержит вручную отобранные играбельные подборки. Для некоторых свежих наборов названия взяты из официальных описаний продукта; ссылка есть у каждой карты. Статистика относится к локальным подборкам, не к размеру оригинальных коробок. Охват — дополнения к классическому фэнтезийному Манчкину, не все самостоятельные игры франшизы. Продукты без проверенных названий карт не добавлялись как пустые колоды.

Обновить открытые списки для исследования: `python3 scripts/fetch-catalog.py` (нужна сеть). Это не изменяет отобранные игровые карты автоматически.

Старые партии сохраняют руки, порядок колод, раунд и прогресс. При загрузке старым картам оружия добавляется информация о числе рук. Новые подборки доступны в новых партиях; в старую партию новые наборы не подмешиваются.

29 тестов покрывают выбор наборов, снаряжение, две руки, мультиклассы/мультирасы, снятие модификаторов, совпадение названий с опубликованными списками, задания и совместимость сохранений.

## Иллюстрации и вмешательство в бой

Для всех 288 карт есть локальная привязка изображения: `public/data/card-art.json`. 280 SVG-файлов Game-icons (CC BY 3.0) хранятся в `public/assets/cards/`. Оригинальные SVG не изменены; CSS использует яркостную маску, индивидуальную палитру и декоративную рамку. Авторство и ссылки есть в приложении, альбоме карт и `ATTRIBUTION.md`. Это подходящие по теме изображения, а не оригинальные иллюстрации настольных карт.

`public/card-illustrations.js` выводит одинаковое изображение карты в руке, бою, снаряжении и альбоме. Альбом открывается из подвала, поддерживает поиск и фильтр набора. Обновить изображения можно командой `python3 scripts/fetch-card-art.py` (нужна сеть; отбор хранится в `scripts/card-art-map.txt`).

В базовый набор и соответствующие дополнения добавлена карта **Wandering Monster / Бродячая тварь**. В чужом бою она позволяет добавить одного монстра из своей руки, расходуя обе карты. Монстр с признаком нежити присоединяется к другой нежити без Бродячей твари. Признак задаётся явно у представленных карт; широкие специальные правила всех семейств монстров пока не моделируются.

Перед заявленной победой или смывкой все соперники по очереди получают окно реакции. Человек может подкинуть монстра, разыграть усилитель на выбранного монстра или спасовать. В hotseat появляется экран передачи устройства; боты ждут ручного ответа человека. После изменения боя награда не выдаётся автоматически: боец пересчитывает силы и принимает новое решение. Боты также подкидывают монстров, когда могут сорвать победу соперника.

Сила, уровни и сокровища всех монстров складываются. Бонус помощника добавляется один раз, доля помощника — одно сокровище за бой. При смывке кубик бросается отдельно для каждого монстра, неудачные броски применяют последствия по отдельности; смерть останавливает дальнейшие броски. По-прежнему упрощено индивидуальное Непотребство большинства карт до потери уровня.

Старые сохранения с одним монстром совместимы с новой моделью боя. Порядок существующих колод сохранён: новые карты Бродячей твари гарантированно входят в новые партии (старые колоды не пополняются новыми определениями).


## Индивидуальные карты и характеры ботов

`public/card-rules-data.js` содержит проверенные параметры и краткие пересказы эффектов с источниками. `public/card-effects.js` обрабатывает ограничения предметов, условные бонусы, непотребства и действия сокровищ. Проверенные правила есть у всех 11 монстров исходных наборов: разные потери карт, вещей и уровней, смерть, смывка без кубика, отсутствие преследования, бонусы против классов/рас/пола и дополнительное сокровище растения эльфу. Помощник тоже отдельно смывается от каждого монстра и получает своё непотребство.

Исправлены руки/бонусы/ограничения посоха напалма, Дикого топора и Протыкатора; добавлены большие шмотки, печатные цены, эльфийский бонус шлема, жертва крысы/наёмника/скакуна, дополнительный скакун от сапог, огненные атаки и уровень Dark за подставу. Перезаряженный кубик используется в отдельном окне после чужого броска смывки (на свой бросок его сыграть нельзя). При выборе карты в оплату или непотребство карта теряется только после подтверждения. Пол персонажа выбирается перед стартом, поскольку некоторые монстры учитывают его.

В деталях карты есть описание, статус проверки и ссылка на источник. `✓` означает проверенный эффект; `◐` — частичные данные или параметры подборки. По уточнению пользователя непроверенные особенности редких карт отложены, авторские эффекты не добавлялись. Собственная колода заклинаний Манчкиномикона, все расширенные способности наёмников, восстановление Pixie Potion и остальные неподтверждённые эффекты пока не реализованы. Некоторая часть исходного адаптированного каталога всё ещё имеет условные числа, это обозначено статусом, а не выдано за оригинальный текст.

`public/ai.js` содержит 10 профилей: Берсерк, Осторожный, Торгаш, Тактик, Дипломат, Саботажник, Охотник, Коллекционер, Мститель и Оппортунист. При старте ботам случайно назначаются разные профили без повторов; выбор и память об обидчиках сохраняются. Параметры влияют на подготовку, продажи, расход карт, выбор монстров, помощь и вмешательства. Все боты пытаются сорвать победный бой соперника и не мешают стороне, которой помогают. В интерфейсе можно нажать профиль бота и увидеть все десять характеров.

Старые партии получают проверенные метаданные карт с сохранением UID, рук, порядка колод и усилителей текущего боя; старые боты без профиля получают стабильного Тактика. Случайные профили назначаются новым партиям. Исследовательские записи лежат в `reference/rules/monster-research.json` и `reference/rules/treasure-research.json`. Отдельные тесты проверяют эффекты, выборы после броска, миграцию и различия поведения, включая независимость решений от чужих скрытых рук.


## Карикатуры для карточек

Первая серия оригинальных рисунков: 11 монстров исходных наборов, Дикий топор, Рогатый шлем и Башмаки могучего пенделя. Рисунки сгенерированы встроенным imagegen. После уточнения пользователя остальные сцены сделаны проще: крупные силуэты, выразительные лица, минимум фона и мелких деталей. В приложение включены компактные JPEG 384×384 (качество экспорта 80), достаточные для карточек и экранов Retina.

Файлы: `public/assets/illustrations/`. Привязка по английскому имени: `public/generated-card-art.js`; одинаковая карта в нескольких наборах получает один и тот же рисунок. `cardArt()` автоматически использует карикатуру в руке, бою, альбоме и экипировке; остальные карты используют прежние SVG. В альбоме кнопка «Новые карикатуры» отбирает только новую серию. Сохранения не требуют перезапуска партии.

Полные запросы генератору и исходные пути: `reference/art/prompts.json`. Оригинальные сканы настольных карт и рисунки издателя для этой серии не использовались. Авторство и CC BY 3.0 в `assets/cards/ATTRIBUTION.md` относятся к оставшимся SVG Game-icons, а не к новым карикатурам.


## Учёт изображений и продолжение генерации

Начинать следующую серию с [реестра иллюстраций](reference/art/README.md). В нём таблица готовых рисунков, ссылки на игровые JPEG и сохранённые оригиналы PNG, точные запросы и очередь оставшихся карт. Машиночитаемые данные: `reference/art/registry.json` и `reference/art/backlog.json`. Очередь учитывает одинаковые карты в разных наборах и исключает готовые рисунки.

`npm run art:sync` пересобирает учёт из записей генерации и игровых привязок, сохраняя недостающие оригиналы в проект. `npm run art:check` проверяет полноту учёта, наличие файлов и SHA-256, ничего не меняя. Генератор изображений эти команды не запускают.


### Полный оригинал и игровая подборка — разные объёмы

Приоритет генерации: сначала полный классический базовый набор, затем дополнения. В `reference/art/base-publisher-list.json` сохранён официальный список: 95 дверей и 73 сокровища, всего 168 печатных карт / 147 уникальных названий. На момент первоначального аудита локальная базовая подборка содержала только 22 определения. Текущую полноту игровых правил показывает отдельный аудит ниже. Универсальная «Получи уровень» не считается иллюстрацией каждой отдельной печатной GUAL-карты.

С версии 2 реестр и очередь учитывают названия из сохранённых списков издателя, включая ещё не импортированные в игровой движок. Поле `playable` отмечает наличие игрового определения; `catalogMembership` хранит набор, печатное название, раздел списка и источник. Приоритет 0 в очереди — база. Счётчик оставшихся SVG относится только к игровым определениям и больше не используется как общий размер всей коллекции.


### Альбом полного оригинала

`http://localhost:4387/base-art.html` показывает все 147 уникальных названий базы, включая карты, пока не подключённые к игровым колодам. Доступны фильтры последней серии, готовых рисунков, всей базы и очереди, поиск и разделение дверей/сокровищ. Ссылка «Полный оригинал» есть в игровом альбоме. Данные `public/base-art-data.js` обновляются командой `npm run art:sync`; отсутствие игровых правил не подменяется выдуманными параметрами.

Готовые генерации из журнала можно подключить командой `npm run art:import -- reference/art/batch-ИМЯ.json`, затем выполнить `npm run art:sync` и `npm run art:check`. Импорт сохраняет PNG в проект, экспортирует JPEG 384×384, записывает точные промпты и обновляет привязки. Повторный импорт готовой записи не генерирует и не заменяет рисунок.


## Проверка состава игровых колод

Актуальный [аудит игровых карт](reference/cards/README.md) отделён от реестра изображений. На 26 октября 2026 года в движке 413 определений / 407 уникальных названий; база содержит все 147 уникальных названий и точно 168 экземпляров: 95 дверей + 73 сокровища. Полные 800+ карт ещё не реализованы. Все существующие определения участвуют при выборе своих наборов независимо от иллюстрации. Искусственные множители ×5/×6 убраны из новых партий; для первых трёх наборов используются известные печатные количества реализованных карт. При выборе всех наборов сейчас 447 физических экземпляров. Старые сохранения сохраняют прежний состав.

[Журнал реализации базы](reference/rules/base-progress.md) содержит источники, оставшиеся карты и ограничения. Наличие определения и отметка «частично» не означают полную сверку печатного текста.

`npm run cards:audit` пересобирает отчёт и `public/data/gameplay-audit.json`: отсутствующие карты по каждому набору, статусы правил, игровые ID, число экземпляров, проверку попадания всех ID в партию. `npm run cards:check` проверяет актуальность без перезаписи. Официальные списки трёх исходных коробок с сохранёнными повторами лежат в `reference/core-publisher-lists.json`. Отчёт не изменяет партии, изображения или правила карт.

## Сетевые лобби и управление игроками

В лобби новой партии есть кнопка **«Сетевые лобби · найти или создать»**. Можно создать открытый стол, найти случайное открытое лобби или войти по ID / названию и паролю. Название стола служит логином закрытого лобби; отдельных аккаунтов пока нет. Для закрытого стола нужен пароль от 4 символов. Доступны до пяти мест: человек, бот или закрытое место. Создатель запускает игру, когда все места для людей заняты. Выбранные перед входом наборы используются при запуске сетевой партии.

Игроки подключаются к **одному и тому же серверу**; ID уникален внутри этого сервера. Движок партии работает во вкладке создателя, сервер передаёт отдельные представления стола и разрешённые действия участников. Гостям не отправляются руки остальных игроков или чужие приватные диалоги. Вкладка создателя должна оставаться открытой; её сеанс и состояние игры сохраняются отдельно от локальной партии. При перезагрузке вкладки соединение восстанавливается. Сервер хранит лобби в памяти: перезапуск сервера закрывает сетевые столы. Автоматический перенос роли создателя и вход нового участника посреди начавшейся партии пока не реализованы.

По умолчанию сервер слушает `127.0.0.1:4387`. Для игры с других устройств в своей сети запусти на компьютере создателя:

```sh
HOST=0.0.0.0 npm run dev
```

Остальные открывают `http://АДРЕС_ЭТОГО_КОМПЬЮТЕРА:4387`. Сам по себе ID лобби не делает localhost доступным через интернет; для игры через интернет нужен доступный всем сервер. Проект сам ничего не публикует и не настраивает роутер.

За одним экраном тип управления каждого места выбирается перед стартом. В текущей партии кнопка **«Игроки / боты»** позволяет передавать место человеку или боту, сохраняя уровень, руку и экипировку. Назначенный боту характер сохраняется при обратных переключениях. В сетевой партии местами управляет создатель через **«Лобби / места»**; вернуть место человеку можно, если за ним есть подключённый участник. При замене участника ботом его ожидающий выбор подхватывается логикой бота; возвращение человеку сохраняет текущий этап партии.
