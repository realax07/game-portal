## Главный порядок

**Одно дополнение за раз: актуализировать полный состав → реализовать карты и их правила → проверить игру → отрисовать и подключить иллюстрации → закрыть дополнение → перейти к следующему.**

- Не начинать иллюстрации дополнения, пока не завершены его игровые определения, эффекты и проверка. Уже существующие рисунки сохранять и переиспользовать.
- Наличие названия, общей заглушки эффекта или картинки не означает готовую карту. Для карты без особого эффекта подтвердить обычные параметры; не придумывать ей особенность.
- Если текст или состав не найден, записать конкретный пробел и источники поиска. Не подменять неизвестное выдуманным эффектом и не отмечать дополнение завершённым. Продолжать доступные задачи текущего дополнения; переносить следующий набор вперёд только после изменения очереди пользователем.
- Все реализованные карты выбранных наборов участвуют в партии независимо от наличия рисунков. Рисование не меняет состав и вероятность добора.
- Иллюстрации делать небольшими партиями **до 8 карт**: сгенерировать → осмотреть → исправить дефекты → подключить → обновить учёт → продолжить. Не запускать весь каталог одной генерацией.
- Новые карты входят в новые партии. При загрузке сохранений не менять самовольно порядок, количество и состав уже выданных карт.
- По умолчанию сохранять текущие три набора: база, «Дикий топор», «Клирические ошибки».

### Согласованные правила проекта

Сохранять при добавлении карт и отдельно учитывать в проверках:

- Обычный победный 10-й уровень — за убийство монстра без помощника. Исключения, явно предусмотренные картами, сохраняются; обычная продажа и обычные карты повышения уровня победного уровня не дают.
- Персонаж также считается человеком, если нет карты расы или не заполнена вся доступная вместимость мультирасы.
- Вещь за 0 золотых можно отдельно сбросить; продажа не приносит за неё денег. Карты с положительной ценой, включая зелья и усилители, должны поддерживать продажу по правилам текущего хода.

## Шаблон работы с каждым следующим дополнением

При переходе к набору создавать здесь подробную карточку по образцу «Дикого топора» и заполнять фактический прогресс:

```md
### Набор: название / ID
Статус: состав → механики → проверка → рисунки → завершён.
Редакция и источники:
Карты: подтверждённых названий X; определений в игре Y; физических экземпляров Z.
Неизвестные тексты/параметры:
Новые механики и зависимости движка:

- [ ] Подтвердить полный состав, специальные колоды и печатные повторы.
- [ ] Сверить тексты существующих карт и найти тексты недостающих.
- [ ] Добавить карты, индивидуальные эффекты, ограничения и награды.
- [ ] Подключить интерфейс решений, журнал, ботов и сохранение состояния.
- [ ] Проверить весь набор и сочетания с уже завершёнными; обновить аудит.
- [ ] Закрыть карты и механики, затем составить очередь рисунков.
- [ ] Подключить и проверить рисунки маленькими партиями, обновляя реестр.
- [ ] Закрыть набор и выбрать следующий в основной очереди.

Проверки и известные ограничения:
Последняя завершённая партия / следующий конкретный шаг:
```

Для подземелий, заклинаний, пыльцы, заданий и других специальных типов сначала реализовать нужные самостоятельные колоды и правила. Не считать текущие упрощения «событие двери» или «обычный бонус» окончательной реализацией.

## Где вести подробный учёт

- [Игровой аудит и покрытие наборов](reference/cards/README.md), [машинный отчёт](public/data/gameplay-audit.json) — составы, совпадения, отсутствующие названия и существующие статусы. Не подменяет сверку эффектов.
- [Списки издателя](public/data/publisher-catalog.json), [печатные списки исходных коробок](reference/core-publisher-lists.json) — отправная точка состава.
- [Состояние правил базы](reference/rules/base-progress.md), [реестр базы](reference/rules/base-implementation.json) — реализованные механики и известные пробелы.
- [Учёт иллюстраций и ссылки на файлы](reference/art/README.md), [точные промпты](reference/art/prompts.json), [очередь рисунков](reference/art/backlog.json) — готовые изображения, происхождение и недостающее. Очередь изображений не определяет очередь реализации карт.
- `reference/art/batch-*.json` — план и результат конкретной партии рисунков; `reference/art/results/` — записи для восстановления после перерыва.
- `reference/qa/` — результаты проверок и скриншоты. После каждой партии здесь в бэклоге указывать, что закончено и с какого места продолжать.

Применимые команды: `npm run cards:audit`, `npm run cards:check`, `npm test`; для изображений — `npm run art:import -- reference/art/batch-ИМЯ.json`, затем `npm run art:sync` и `npm run art:check`. Проверки выбирать по изменениям: работа только с картинками не требует повторять всю игровую проверку.
